# 论文研究前端产品方案 · v0.1

状态：已实现本地前端，并新增 Windows 桌面启动程序与 Codex 订阅终审。双击 `dist/PaperAtlas/PaperAtlas.exe` 使用；当前能力以 [桌面应用说明](desktop-app.md) 为准。本稿以下保留最初产品规划。

后续更新 v0.2：新增“文献查询”入口，用户在“我的研究需求”中自由写明想看算法、实验数据或其他具体内容，不使用固定研究重点分类。支持已配置的 Flash 模型选择、日期筛选、自然语言生成检索式、候选预览、主动开始阅读、任务停止，以及论文发表时间升降序排列。此下方方案保留为首版设计记录，当前运行方式以 README 为准。

本稿依据现有论文筛选、Flash 阅读、多模型接入、证据校验、外部/API 终审及多轮研究产物设计。所有本次新增文件均位于当前项目目录。

## 1. 产品定位与默认范围

**产品定位：本地论文研究结果工作台。** 让使用者能读懂综述、比较论文、回查依据，并知道哪些内容仍需审阅。

第一版先按以下假设设计，均可调整：

- 主要由你个人在电脑上使用，优先适配桌面浏览器，中文界面。
- 打开后优先阅读研究结果；运行监控作为次级入口。
- 首版以读取既有研究产物为主，查看页面不会触发模型请求或改变研究结果。
- 数据保存在本地；不要求账号、云同步或在线发布。
- 模型角色沿用当前规则：下层 Flash，上层审阅者可替换。

用户应能迅速回答四个问题：这轮研究得出了什么结论？哪些论文支撑这些结论？证据在哪里？还有什么未解决？

## 2. 信息架构

建议采用四个主入口，避免按产物文件逐个建立菜单。

| 入口 | 用户目的 | 主要内容 |
|---|---|---|
| 研究结果（默认） | 连贯阅读整轮研究 | 综述、目录、分类、技术脉络、证据侧栏 |
| 论文库 | 找论文、精读和比较 | 搜索、标签、阅读卡片、2–4 篇对照 |
| 审阅与问题 | 明确哪些判断尚不可靠 | 审阅记录、覆盖缺口、待补读问题、版本状态 |
| 运行记录 | 看轮次、进度与消耗 | 历史运行、已完成任务、失败原因、来源与用量 |

顶部全局区域：研究主题选择、轮次/运行选择、报告版本、数据更新时间。模型配置在后续加入运行控制时放入设置入口。

同一轮可能有多次运行，顶部需要同时显示“第几轮”和具体运行时间，不能只用轮次编号区分。不同轮的 P01 也必须有独立身份。

## 3. 默认页面：研究结果

### 3.1 页面布局

以下为低保真布局，方括号表示可点击区域，文字与数值均为布局示例。

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 论文研究工作台    [研究主题 ▾] [第 1 轮 · 运行日期 ▾]    [报告版本 ▾] │
├───────────┬────────────────────────────────────────────────────────────┤
│ 研究结果  │ 研究主题                                      [导出 ▾]   │
│ 论文库    │ 研究问题：本轮希望回答什么？                               │
│ 审阅与问题│ 阅读 32/32 · 待终审 · 来源限制 2 篇（示例）               │
│ 运行记录  ├──────────┬────────────────────────────┬──────────────────┤
│           │ 文章目录 │ 综述正文                   │ 证据侧栏         │
│           │ 摘要     │                            │ 点引用后打开     │
│           │ 范围方法 │ 可点击引用 [P01]           │                  │
│           │ 分类综述 │ 方法、比较与限制           │ 论文标题 / 年份  │
│           │ 跨论文发现│                           │ 贡献 / 实验条件  │
│           │ 开放问题 │                            │ 引文 / 页码      │
│           │ 参考文献 │                            │ [查看上下文]     │
└───────────┴──────────┴────────────────────────────┴──────────────────┘
```

证据侧栏默认关闭，保证正文阅读宽度；打开时保留当前位置。窗口较窄时，侧栏改为覆盖式抽屉，主导航和目录收起。正文不因布局变化丢失滚动位置。

### 3.2 内容与默认行为

- 有有效定稿时默认读定稿；可切换查看草稿和审阅记录。
- 新版定稿须结合审查决定与文件一致性检查确认状态，不能仅凭存在最终报告文件显示“已通过”。
- 只有草稿时明确标记“待审阅草稿”。
- Flash 阅读完成但没有综述时，显示“阅读卡片已就绪，等待上层综合与审阅”，提供分类浏览和卡片入口。
- 没有生成的摘要时，不为了填充首页再自动调用模型生成一份“结论摘要”。
- 主分类来自最终审阅结果；阅读阶段的多个标签作为辅助标签，避免同一篇被误算为多篇。

### 3.3 核心交互：正文 → 论文 → 证据 → 原文

1. 点击正文中的 `[P01]`，打开对应论文卡片。
2. 先显示一句话总结、贡献、实验条件和局限；证据区域显示现有“主张—引文”对。
3. 点击某条证据，展示原文片段及前后上下文、声明页码、实际定位页码和来源限制。
4. 支持打开论文原始链接；有本地原文时可继续查阅提取文本。
5. 关闭侧栏后继续阅读原来的正文段落。

**现有引用只足以准确定位论文。** 第一版应标明“该论文的证据”，不能暗示某条引文已精确支撑当前点击的整句话。报告结论与具体证据的逐条绑定，需要后续补充稳定的结论、证据标识。

提取文本视图为首版必做；内嵌 PDF 和精确高亮需额外保存或获取 PDF，列入后续范围。历史记录只有引句时，展示现有引句和论文链接，并注明“未保存原文上下文”。

## 4. 论文库与比较

### 4.1 论文列表

默认显示当前轮入选论文，包括失败项；可切换累计论文或候选筛选记录。常用字段为标题、年份、最终主分类/暂定标签、来源状态、阅读状态，以及是否存在待解决问题。

搜索覆盖标题、作者、研究问题和方法描述。筛选包括分类、年份、轮次、全文/摘要、阅读失败、存在审阅问题。模型来源放在详情中，必要时展开筛选，不占据列表主体。

累计视图按论文身份去重，并保留各轮阅读版本；一篇论文的多个分析版本不能互相覆盖。缺少历史正文的累计条目只显示已有元数据，并给出所属轮次入口。

详情内容顺序：论文摘要与研究问题 → 方法与贡献 → 实验设置与发现 → 局限 → 原文证据 → 阅读模型与记录。

### 4.2 横向比较

勾选 2–4 篇论文，进入并排比较；窄屏优先比较两篇。各列固定对应论文，各行对应研究问题、机制、实验设置、关键发现、代价与局限、证据。

```text
┌──────────────┬─────────────────────┬─────────────────────┐
│ 比较维度     │ 论文 A              │ 论文 B              │
├──────────────┼─────────────────────┼─────────────────────┤
│ 解决的问题   │ 原阅读卡片内容      │ 原阅读卡片内容      │
│ 核心机制     │ 原阅读卡片内容      │ 原阅读卡片内容      │
│ 实验设置     │ 硬件、模型、负载等  │ 硬件、模型、负载等  │
│ 结果与条件   │ 结果须与条件同显    │ 结果须与条件同显    │
│ 代价与局限   │ 已记录的限制        │ 已记录的限制        │
│ 原文证据     │ [查看]              │ [查看]              │
└──────────────┴─────────────────────┴─────────────────────┘
```

首版沿用现有文本字段，保留“不详/未报告”，不额外自动抽取数值。不得直接将不同硬件、模型、负载下的性能数字做成排行榜。后续若要绘制可比性能图，先建立结构化实验条件与可比性规则。

## 5. 分类与技术脉络

技术脉络位于“研究结果”内，与正文切换，不单独占据主导航。

首版提供：分类论文数量、分类列表、按发表年份排列的论文时间轴。时间轴只表达发表时间，年份缺失的论文放入“时间未记录”区。

可选关系视图按类别展开，关系区分直接改进、机制扩展、替代、正交研究与评测。点击关系必须显示依据、相关论文及审阅状态。

这里存在一个必须明确的数据边界：当前 API 草稿可能有结构化关系，但外部审阅的定稿可能只有修订正文和最终分类。草稿中的关系还可能已被终审否定。因此：

- 无终审确认的结构化关系时，不生成“最终技术关系图”。
- 有草稿关系时，可在明确标为“草稿关系”的独立视图查看，不与定稿混用。
- 缺少关系数据时，保留分类列表、时间轴和综述正文，说明“暂无经确认的结构化关系”。
- 按年份排列不能自动产生继承箭头；主题相近也不能自动标成“改进前作”。

建议第二阶段补充经审阅确认的关系数据，再做可筛选的关系图。大规模自由拖拽网络图不作为首版主界面。

## 6. 审阅、状态与运行信息

### 6.1 状态分开显示

| 维度 | 示例状态 | 不应混淆的含义 |
|---|---|---|
| 运行 | 进行中、已中断、失败、阶段已结束 | 运行结束不代表报告获批 |
| 报告 | 尚未生成、草稿、待审阅、待修订、已批准、批准已失效 | 新内容产生后旧批准可能失效 |
| 阅读覆盖 | 28/32、32/32 | 32 篇读完不等于全部事实正确 |
| 来源 | 已保存提取全文、阅读输入有截断、仅摘要、历史未记录 | 已有全文与模型实际读到全文应分别表达 |
| 证据 | 引句匹配、页码存在差异、上下文不可用 | 引句匹配不等于事实或推论已验证 |

模型的 `confidence` 若保留，只在详情中标为“模型自评”；不转化为论文质量分、事实正确率或默认排名。

### 6.2 审阅与问题页

显示实际审阅者、审阅方式、当前决定、审阅记录、覆盖缺口和补读问题。问题列表说明涉及哪篇论文、需要核验什么以及为什么需要补读；状态不应只显示错误代码。

首版支持查看和复制待补读问题、导出现有审查材料。页面内执行补读、提交审阅结果、编辑正文和定稿放入第二阶段，届时必须保存版本并复用现有校验规则。外部审阅模式应明确显示“等待外部审阅结果”，不模拟后台正在自动审阅。

### 6.3 运行记录页

展示主题、轮次、运行时间、目标/有效/失败篇数、筛选与阅读模型、实际生产模型、审阅者、状态、已记录请求数与用量。支持查看失败原因和现有诊断记录。

首版按已写入的产物刷新，并显示最近读取时间。现有系统没有完整的实时阶段事件、逐任务耗时和剩余时间记录，不能承诺精确进度百分比、ETA 或实时调用时间线。后台是否仍存活也不能只凭一个旧的“running”字段判断。

用量区分供应商报告值、保守估算和未知。Token 预算不显示成人民币/美元余额；历史用量不完整时不能填 0。

## 7. 首版范围与后续范围

| 优先级 | 范围 | 交付标准 |
|---|---|---|
| 首版必做 | 本地研究记录加载、主题与轮次切换 | 能打开当前目录中的既有新旧产物 |
| 首版必做 | 综述排版、目录、论文引用与证据侧栏 | 阅读不需要手动找 JSON 文件 |
| 首版必做 | 论文库、筛选、2–4 篇文本比较 | 能按问题和方法找到及对照论文 |
| 首版必做 | 最终分类、分类分布和发表时间轴 | 有直观结构，缺失数据不编造 |
| 首版必做 | 审阅状态、问题和来源限制 | 看得出哪些内容还不能当定稿 |
| 首版必做 | 查看运行记录、刷新、导出现有报告 | 浏览不触发付费请求或改写原结果 |
| 下一阶段 | 页面内补读、模型选择、启动与续跑 | 接入本地任务服务与状态反馈 |
| 下一阶段 | 经终审确认的关系图、逐条结论证据定位 | 先扩展结构化审阅数据 |
| 下一阶段 | 收藏、个人笔记、版本对比 | 个人记录与原研究结果分开保存 |
| 下一阶段 | PDF/Word 排版导出、内嵌 PDF | 单独确认格式、引用与布局要求 |
| 暂不纳入 | 多人权限、云同步、公开分享、聊天问答 | 避免首版范围失控，按后续需求评估 |

如果你希望第一版就是完整研究工作台，可以把“启动任务、模型选择、补读操作”前移；相应需要同时设计任务服务、预算提示、状态更新和操作后的版本变化。

## 8. 视觉与交互基调

建议采用浅色、低饱和的阅读界面，深色文字，蓝绿色表示导航和选择；橙色表示待处理问题。状态同时使用文字和图标，不能只靠颜色。正文保持舒适行宽，表格优先可读，长引文折叠但可展开完整上下文。

首页不堆模型数量、成功率圆环和大图标。只有能回答研究问题的图才进入内容区：分类分布、发表时间轴、论文对照和有依据的关系。

草稿、定稿、用户笔记和原文引句使用明确标签。键盘可以打开/关闭侧栏，筛选后能返回原列表位置；加载失败时保留其他可用内容。

## 9. 现有能力与需要补齐的部分

| 页面能力 | 现有基础 | 前端落地时的补充工作 |
|---|---|---|
| 阅读报告与论文卡片 | Markdown、结构化阅读结果 | 统一读取、排版、搜索及引用跳转 |
| 查看原文证据 | 新记录有原文和上下文；旧记录可能只有引句 | 新旧数据适配与缺失说明 |
| 跨轮查看论文 | 有轮次、父轮和累计元数据 | 稳定研究/运行标识、去重后的版本入口 |
| 查看最终主分类 | 新版批准决定及分类文件 | 区分最终分类与阅读标签 |
| 展示最终关系图 | 草稿有时有关系，定稿不保证结构化 | 增加终审确认的关系清单及依据 |
| 精准定位句子证据 | 当前正文引用多为论文级 | 增加结论、证据与正文锚点的关联 |
| 实时运行控制 | 有 CLI，没有前端任务服务 | 新增启动/补读/续跑接口、事件与存活检查 |
| 金额费用 | 有请求/token 记录，无完整统一价格账本 | 如需金额，补模型价格版本和未知用量处理 |

实现时需要本地读取服务或显式的文件夹导入机制；普通网页不能假定拥有任意本地目录访问能力。本稿倾向本地服务，以支持自动发现历史运行；技术框架暂不在本轮决定。

兼容当前历史记录时，应按实际导入目录和文件结构定位内容。部分历史清单保存的是项目搬迁前的绝对路径，不能依赖这些旧路径，也不能为适配界面改写历史原件。

旧报告没有新版批准凭据时显示“历史记录：已完成；缺少新版一致性验证”，不冒充刚通过新版终审。关系图也不得优先读取旧草稿而忽略最终正文修订。

## 10. 首版验收场景

1. 打开已有完成轮次，直接进入可读综述，不需要查文件名。
2. 点击 `[P01]`，两步内看见该论文的证据和来源限制，关闭后不丢失正文位置。
3. 同时比较两篇论文时，发现和实验条件都可见，不产生跨设置性能排名。
4. 一轮只有 28/32 篇有效结果时，研究结果、论文库和审阅页均能看见覆盖缺口。
5. 打开 external 模式的阅读完成记录，即使没有 Pro 草稿也能浏览论文与证据。
6. 历史记录缺少全文、来源模型或批准凭据时仍能阅读，缺项标为未记录。
7. 切换两个轮次的 P01，分别定位到正确论文；累计列表不重复计数。
8. 没有经终审确认的关系数据时，时间轴和分类可用，不出现虚构继承箭头。
9. 数据刷新后发现批准失效，清楚标示当前内容待审；若仍有旧定稿文件，标为历史版本。没有保存的旧版本不能假装可以恢复。
10. 单纯打开、搜索、比较与导出既有报告，不调用模型、不覆盖原始研究结果。

## 11. 请你优先评审的选择

本稿先按结果阅读优先起草，以下选择最影响后续设计：

- **第一版范围**：先把结果看清楚，还是同时在页面上启动研究和选模型？
- **默认阅读方式**：先看整篇综述，还是先看逐篇论文卡片？
- **关系可视化**：分类与时间轴是否足够，还是技术关系图必须首版就有？
- **个人整理**：是否需要收藏、阅读标记和自己的笔记？
- **交付格式**：现有 Markdown 是否够用，还是 PDF、Word 或汇报材料更重要？

后续按你的反馈调整此稿，先确认页面范围和关键交互，再进入视觉原型与前端实现。
