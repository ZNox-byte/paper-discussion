# 以 vLLM 为代表的 AI Infra Systems 论文综述（Codex 审查版）

> 研究流程：DeepSeek v4 Flash 初筛与逐篇分析 → DeepSeek v4 Pro 分类汇总 → Codex GPT 内容审查与关系修订。

## 摘要

本综述覆盖 32 篇以 vLLM 及其相邻系统为中心的 AI Infra 论文。材料显示，这一领域并非沿单一系统代际前进，而是围绕五个相互制约的系统资源展开：GPU 执行时隙、KV Cache 容量与位置、跨设备数据移动、服务级目标，以及正确性与隔离性。PagedAttention 把 KV Cache 的动态块管理变成服务系统的基础能力 [P01]；此后研究分别从虚拟内存与 token 粒度回收 [P03][P24]、前缀与非前缀复用 [P02][P09]、多级存储和细粒度放置 [P11][P17][P18][P19][P23]、压缩与量化 [P07][P10][P20][P21][P22][P25][P26] 等方向扩展。与此同时，请求调度从单 GPU 内的流水与资源分区 [P05][P15]，扩展到公平性、混合优先级、跨实例控制和动态解耦 [P06][P12][P13][P14][P16][P27]。评测、确定性、协同训练和模糊测试工作进一步说明，吞吐并不是唯一目标；真实负载、能耗、输出一致性、SLO 和可靠性必须共同进入系统设计 [P04][P28][P29][P30][P31][P32]。

## 范围、方法与关系标记

为避免把“相关性”写成“因果继承”，下文采用以下关系语义：

- **基础**：在本轮语料中作为该问题线的起点。
- **机制扩展**：扩展相同抽象或目标，但不必然证明作者层面的直接继承。
- **直接扩展**：设计问题和优化变量连续；仍不等同于已核实的论文引用谱系。
- **替代/分支**：解决相近问题，但采用不同系统机制。
- **评测/约束**：不提供同类优化，而是测量、验证或暴露边界。

## 1. 推理服务与请求调度

### 1.1 单 GPU：从资源重叠到动态资源隔离

P05 NanoFlow 是吞吐导向的基础路径：它把请求拆成 nano-batch，在单 GPU 内重叠计算、内存和网络操作，目标是让多个硬件资源同时接近饱和 [P05]。P15 Nexus 处理相邻但不同的问题：它在同一 GPU 内主动逻辑解耦 prefill 与 decode，以动态 SM 分区和成本模型在 TTFT、TBT 与吞吐之间调整资源 [P15]。两者应读作并行机制，而不是 P05→P15 的已证实继承链：NanoFlow 强调流水与重叠，Nexus 强调阶段隔离和资源控制。

P16 BROS 又引入工作负载等级这一维度，通过迭代级动态优先级和双向 KV 块共享，让实时请求与尽力而为请求共置 [P16]。因此，单 GPU 调度的演进并不是简单地“切得更细”，而是从硬件利用率进一步转向阶段隔离与服务等级联合控制：P05 提高资源重叠，P15 调整 prefill/decode 的相对资源，P16 则决定不同优先级请求如何共享同一引擎 [P05][P15][P16]。

### 1.2 公平性：上下文切换成本与缓存局部性

公平调度会频繁抢占请求，而 KV 状态换入换出可能抵消公平策略的收益。P12 FastSwitch 以动态块组、异步交换和跨轮次 KV 复用降低公平调度中的上下文切换开销 [P12]。P13 则把公平性与前缀缓存局部性放在同一目标中，通过局部性感知的公平调度提升缓存命中机会 [P13]。两者构成自然的研究次序——先压低抢占的状态切换成本，再把公平决策本身变得缓存感知——但本轮证据不足以声称 P13 直接改进 P12，故将它们标为问题轨迹上的机制相关工作 [P12][P13]。

### 1.3 跨实例与动态解耦：三条替代控制路径

P06 Llumnix、P27 QLM 与 P14 DynaServe 都面向动态负载和 SLO，却选择了不同控制对象。Llumnix 通过运行时请求重调度和 KV Cache 迁移，在实例间完成负载均衡、去碎片化、优先级隔离和扩缩容 [P06]。QLM 以请求等待时间估计和全局队列管理为核心，通过请求拉取、驱逐、负载均衡与模型切换控制 SLO [P27]。DynaServe 则把请求抽象为可在 token 边界切分的 micro-request，以两级调度统一共置与分离式执行，并支持跨实例状态传递 [P14]。

这三项工作不应被串成 P06→P27→P14。更准确的结构是：P06 以“迁移已有状态”调节实例负载，P27 以“控制队列和模型位置”调节等待时间，P14 以“改变可调度单元和执行拓扑”获得弹性 [P06][P27][P14]。它们的共同开放问题是控制开销、预测误差、KV 移动成本和更大集群规模下的稳定性。

## 2. KV Cache 与内存管理

### 2.1 分配粒度：块、虚拟页与 token

P01 PagedAttention 将 KV Cache 切成可按需分配的非连续物理块，并以块表完成地址映射和共享，奠定了 vLLM 的核心内存抽象 [P01]。围绕这一基础出现两条方向。

第一条是替代路线。P03 vAttention 使用 CUDA 虚拟内存把连续虚拟地址与按需物理映射解耦，避免为分页布局重写注意力内核；它针对 PagedAttention 的块表管理和内核耦合提出不同取舍，而不是 PagedAttention 的简单升级 [P01][P03]。第二条是机制扩展。P24 vToken 保留 PagedAttention 的块管理和内核兼容性，在其上增加 token-table 间接寻址与异步重打包，以回收块内由 token 级驱逐造成的碎片 [P01][P24]。因此这组关系应写成“P01∥P03，P01⇢P24”，而不是 P01→P03→P24。

### 2.2 复用语义：从共享前缀到非前缀知识融合

P02 SGLang 通过 RadixAttention 以 radix tree 管理共享前缀，并将缓存复用与结构化生成运行时结合 [P02]。P09 CacheBlend 面向 RAG 中多个预计算知识块不构成单一共享前缀的情况，选择性重算少量 token，使不同块的 KV Cache 恢复跨块注意力信息 [P09]。从系统抽象看，P09 把“可复用上下文”的范围从前缀扩大到需要融合的非前缀知识块；这是复用机制的研究轨迹扩展，但并不在本次材料中被证明为作者层面的直接后继 [P02][P09]。

### 2.3 多级存储与 I/O：一个基础、多个介质分支

P11 Pensieve 以多轮对话为场景，在 GPU/CPU 多级缓存中保存历史 KV，并扩展非连续内存上的多 token 注意力，代表状态化服务和多级缓存的基础路径 [P11]。此后的系统不应排成单一线性链，而应按介质和数据路径分支：

- P17 Tutti 让 GPU 直接驱动 SSD-backed KV 对象存储，并以 slack-aware I/O 调度降低 CPU 干预 [P17]。
- P18 TraCT 使用机架级 CXL 共享内存兼任 KV 传输介质和前缀缓存，目标是减少传统网络数据路径的跳数 [P18]。
- P19 Strata 通过 GPU 辅助 I/O、分层上下文缓存和缓存感知调度，把碎片化 KV 加载与计算重叠 [P19]。
- P23 OrbitFlow 不绑定某一种外部介质，而是按请求、按层动态决定 GPU/CPU 放置，并把决策与 SLO、暂停和恢复联动 [P23]。

这些工作共同把“容量扩展”变成“数据位置、移动路径和调度时机”的联合问题，但 P17、P18、P19 是兄弟分支，P23 是更细粒度的 SLO 放置分支；本轮证据不支持把它们叙述为依次替代前作 [P11][P17][P18][P19][P23]。

### 2.4 压缩、驱逐与正确性：优化目标逐步扩大

P20 AdaptCache 在 DRAM/SSD 层级中为 KV 条目自适应选择压缩算法、压缩率和设备位置 [P20]。P21 EVICPRESS 将优化变量进一步扩大，用统一效用同时决定有损压缩和跨层驱逐 [P21]。两者具有明确的设计目标连续性，可视为“自适应放置与压缩”到“压缩—驱逐联合优化”的直接扩展；需要特别纠正的是，P20 本身并非固定压缩策略 [P20][P21]。

P22 VeriCache 走的是正确性分支：压缩 KV 用于草稿生成，全量 KV 用于验证，从而把有损表示的性能收益与最终输出一致性分开处理 [P22]。它与 P20/P21 共享“如何利用有损 KV”的背景，但不是这条存储效用链的下一步；它改变的是正确性保障机制，并需要保留全量 KV，形成新的存储—验证权衡 [P20][P21][P22]。

## 3. 模型压缩与低精度计算

### 3.1 KV 表示：2-bit、传输编码与软硬件协同

P07 KIVI 以 key 按通道、value 按 token 的非对称 2-bit 量化降低 KV Cache 占用，是本轮低比特 KV 路线的基础 [P07]。P25 MiniKV 在相同问题线上进一步考虑层间差异，以金字塔式逐层预算和 FlashAttention 兼容的两遍内核联合优化 2-bit KV [P25]。因此 P07⇢P25 是合理的方法级细化；但这里表达的是技术连续性，不把它扩大为未经独立核实的引用谱系 [P07][P25]。

P10 CacheGen 的目标不同：它利用 delta 编码、分层量化和算术编码将 KV 变成可流式传输的 bitstream，并随带宽调整压缩级别，重点是上下文加载和网络 TTFT [P10]。P26 Oaken 又是一条软硬件协同分支，把异常值阈值等决策移到离线阶段，在线完成轻量量化，并配合定制量化/反量化引擎和内存管理单元 [P26]。所以这一组更适合写成 P07⇢P25、P10 与之正交、P26 为混合量化及硬件实现分支，而不是四篇首尾相接 [P07][P10][P25][P26]。

### 3.2 计算内核：低精度注意力

P08 INT-FlashAttention 不压缩持久化 KV 状态，而是把 INT8 后训练量化带入 FlashAttention 前向计算，并用 INT8 GEMM 替换矩阵乘法 [P08]。它与 P07/P25/P26 共享低精度目标，却优化不同资源瓶颈：前者是注意力计算和内核数据路径，后者主要是 KV 容量与带宽。因此 P08 应独立为算子分支，并可在未来与 KV 表示优化组合，而非被放入同一量化代际链 [P07][P08][P25][P26]。

## 4. 并行执行与训练协同

P31 TBIK 关注张量并行规模变化造成的浮点归约顺序差异。它以固定树形归约约束 GPU 内矩阵乘与 GPU 间 All-Reduce，使不同 TP 规模的推理保持确定性，并面向强化学习管线中的训练—推理概率失配 [P31]。这项工作说明，分布式执行的目标不仅是扩展吞吐，还包括跨部署形态的数值一致性；其主要张力是确定性与生产性能之间的开销 [P31]。

P32 DeltaServe 研究另一类资源共享：在不增加硬件的情况下，把在线推理的空闲容量转化为 LoRA 微调吞吐，并以 SLO 感知调度、CUDA-graph 感知延迟模型和独立反向子进程保护推理延迟 [P32]。它与推理调度论文共享 SLO 和抢占问题，却多出训练激活、反向传播和 CUDA Graph 兼容性约束。P31 与 P32 均处于训练—推理边界，但前者解决数值一致性，后者解决容量协同，不构成顺序关系 [P31][P32]。

## 5. 性能评测、成本与真实负载

P04 BurstGPT 发布长期真实服务轨迹，揭示并发突发、对话结构、响应长度和失败等生产特征，为服务系统脱离平稳合成负载提供基础 [P04]。P28 ServeGen 同样从生产负载出发，覆盖语言、多模态和推理模型，并引入按客户端组合的工作负载生成 [P28]。两者形成从“公开与刻画真实轨迹”到“扩大模型形态并生成负载”的研究轨迹，但本次材料不足以证明 P28 是 P04 的直接论文后继 [P04][P28]。

P29 则是正交的配置评测层：它系统改变 vLLM 的注意力内核、前缀缓存与分块预填等配置，同时测量能耗、性能和准确率，显示系统开关的效果依赖模型与任务，甚至可能影响输出准确率 [P29]。P04/P28 回答“应使用什么负载”，P29 回答“在给定负载与任务下应测哪些权衡”；高可信评测需要把两者结合，而不是把 P29 当成工作负载数据集的下一代 [P04][P28][P29]。

## 6. 可靠性、弹性与可观测性

P30 GRIEF 把带时间的多请求轨迹作为灰盒模糊测试输入，并以多类预言机和受控重放发现 vLLM、SGLang 中的缓存隔离、跨请求干扰与崩溃/存活问题 [P30]。它不是又一项吞吐优化，而是对整个优化栈施加约束：缓存共享越积极、批处理和调度越复杂、跨请求状态越多，隔离性与重现缺陷的难度越高 [P01][P02][P30]。

可靠性因此不应只作为报告末尾的补充指标。P30 表明，调度器、KV 管理器和运行时必须提供足够遥测、可重放轨迹与结构性不变量，才能把静默状态污染和尾延迟异常变成可诊断事件 [P30]。这也与 P31 的确定性目标相呼应：一个方向约束分布式数值顺序，另一个方向约束并发服务行为，二者共同推动可复现的 AI Infra [P30][P31]。

## 7. 横切层：硬件与内核不是孤立类别

本轮没有论文被唯一归入“异构硬件与内核优化”，但这一维度贯穿多个主分类。P03 依赖虚拟内存页映射与驱动能力 [P03]；P08、P25 通过专用注意力内核把低精度算法转化为端到端收益 [P08][P25]；P17、P18、P19 分别围绕 SSD、CXL 和 GPU 辅助 I/O 重构数据路径 [P17][P18][P19]；P26 把量化算法与定制引擎、MMU 联合设计 [P26]；P31 同时约束计算内核与通信归约 [P31]。因此，硬件/内核更适合作为所有系统机制的实现层，而不是为保持分类对称性强行复制论文。

## 8. 跨论文综合

### 8.1 优化对象从单一资源转向联合状态

早期或基础系统常把一个瓶颈变成可管理抽象：PagedAttention 管块 [P01]，NanoFlow 管流水 [P05]，KIVI 管低比特 KV [P07]。后续系统逐渐同时决定多个变量，例如公平性与缓存局部性 [P13]、压缩与驱逐 [P21]、KV 放置与 SLO [P23]、prefill/decode 与 SM 资源 [P15]、推理延迟预算与微调准入 [P32]。联合优化带来更好的全局目标，也增加了模型误差、控制稳定性和可解释性风险。

### 8.2 KV Cache 已从内存对象变成跨系统状态

KV Cache 同时决定显存容量 [P01][P24]、内核布局 [P03]、前缀/知识复用 [P02][P09]、抢占成本 [P12]、跨实例迁移 [P06][P14]、多级存储 I/O [P11][P17][P18][P19][P23]、有损表示与正确性 [P20][P21][P22]。因此，单独优化某一层很容易把成本转移到另一层：更强压缩可能增加计算或质量风险，更细放置可能增加规划开销，更广复用可能扩大隔离面。

### 8.3 SLO 正在替代纯吞吐成为控制接口

P12、P16、P23、P27、P32 分别把公平抢占、混合请求等级、KV 放置、全局排队和训练准入与延迟目标连接 [P12][P16][P23][P27][P32]。P06 与 P14 则用动态实例控制和执行拓扑适配负载 [P06][P14]。共同趋势是：系统不再只报告峰值吞吐，而是持续估计剩余延迟预算，并据此改变状态位置、资源份额或请求路径。

### 8.4 评测必须包含负载真实性、准确率与故障面

P04/P28 说明平均到达率无法代表生产突发与客户端异质性 [P04][P28]；P29 说明配置优化可能改变能耗、延迟甚至准确率 [P29]；P30 说明并发状态交互还可能产生安全和可靠性缺陷 [P30]。一个更完整的 serving benchmark 因而至少需要真实到达过程、长上下文/多轮复用、模型与任务多样性、能耗与质量指标，以及并发故障注入或重放。

## 10. 研究空白

1. **统一的跨层控制面。** 当前调度、KV 放置、压缩率和硬件路径常由独立启发式控制。需要能表达 SLO、质量、能耗和可靠性约束的统一接口，并避免多个控制环相互振荡 [P14][P21][P23][P27]。
2. **有损 KV 的可验证质量模型。** P20/P21 优化压缩与存储效用，P22 通过全量验证保护输出；尚缺少既能预测逐请求质量、又不保留高成本全量状态的通用方法 [P20][P21][P22]。
3. **分布式与异构规模验证。** 多项工作仍以单节点或有限 GPU/介质为主；SSD、CXL、跨实例迁移、细粒度放置和确定性内核需要在更大集群与故障条件下联合评估 [P06][P14][P17][P18][P23][P31]。
4. **组合优化的非加和效应。** KV 淘汰、量化、前缀复用、分块预填和专用内核组合后可能互相削弱，P25 与 P29 已提示配置或算法效果对任务和组合敏感 [P25][P29]。
5. **从性能可观测性走向状态正确性可观测性。** 系统需要公开足够的缓存归属、请求轨迹、调度决策和重放接口，使 P30 类型的缺陷能在持续集成和生产环境中被发现 [P30]。
6. **训练—推理边界的共同基准。** P31 关注概率匹配，P32 关注容量共享；未来基准应同时测量数值一致性、推理 SLO、训练吞吐和抢占恢复成本 [P31][P32]。
7. **长期、多提供商真实负载。** P04 与 P28 的数据仍受提供商、时间跨度和隐私限制；评测社区需要可比较、可更新又能保护用户数据的长期负载表示 [P04][P28]。

## 结论

以 vLLM 为代表的 AI Infra Systems 正从“单点消除浪费”进入“跨层管理状态”的阶段。PagedAttention 把 KV 内存变成可调度资源 [P01]，随后不同系统继续改变它的地址粒度、复用语义、存储位置、精度和正确性机制 [P02][P03][P09][P17][P18][P19][P20][P21][P22][P23][P24]。请求侧则从单 GPU 流水扩展为跨优先级、跨实例和跨训练/推理边界的动态控制 [P05][P06][P12][P13][P14][P15][P16][P27][P32]。

真正可持续的下一步不会只追求更高吞吐，而会把真实负载、能耗、输出质量、数值确定性和并发可靠性纳入同一评价体系 [P04][P28][P29][P30][P31]。本轮最重要的审查结论也与此一致：分类可以提供阅读入口，但技术发展常是分叉网络而非单线谱系；只有在证据充分时，才应把“相关工作”写成“后作改进前作”。
